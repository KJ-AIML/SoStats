# Stage 7 — Provider #2: X

Stage 7 adds X as the second real social provider and hardens the provider OAuth
boundary for both X and LinkedIn.

## Why Provider #2 matters

A second provider is an architecture test, not just another logo.

The same SoStats pipeline now targets two independent APIs:

```text
Content / Variant
  -> Schedule
  -> Publishing Worker
  -> SocialPublisherPort
       -> LinkedIn
       -> X
  -> publication_results
  -> Analytics Worker
  -> SocialAnalyticsPort
       -> LinkedIn analytics
       -> X post metrics
  -> AI learning loop
```

No X-specific logic is required in Scheduling, Publishing, Analytics, or the
recommendation engine.

## X API surface

The adapter uses X API v2 user-context OAuth.

Publishing:

```text
POST https://api.x.com/2/tweets
```

Account identity:

```text
GET https://api.x.com/2/users/me
```

Metrics:

```text
GET https://api.x.com/2/tweets/:id?tweet.fields=public_metrics,non_public_metrics
```

SoStats maps:

- impressions
- likes -> reactions
- replies -> comments
- reposts + quotes -> shares
- bookmarks -> saves
- URL link clicks -> clicks when private metrics are available

If the account/API access cannot return private metrics, the adapter falls back
to public metrics instead of losing the whole analytics snapshot.

## OAuth 2.0 + PKCE

X uses Authorization Code Flow with PKCE.

Requested scopes:

```text
tweet.read tweet.write users.read offline.access
```

`offline.access` is required for a refresh token so scheduled publishing can
continue after the short-lived access token expires.

SoStats uses S256 PKCE:

1. API creates a random code verifier.
2. Only its SHA-256 challenge is sent to X.
3. The verifier is stored inside encrypted callback state.
4. X redirects to the SoStats API callback.
5. The API decrypts/validates state and exchanges the short-lived code.
6. Tokens are encrypted before persistence.

The PKCE verifier is never exposed as plaintext in the authorization URL.

## OAuth state hardening

The old LinkedIn adapter created a random `state` value but there was no
end-to-end callback validation path.

Stage 7 replaces that with one provider-neutral flow.

State contains:

- workspace id
- brand id
- provider
- exact callback URI
- safe relative return path
- optional PKCE verifier
- random nonce
- expiry

The whole state payload is AES-256-GCM encrypted and authenticated using
`OAUTH_STATE_SECRET`. It expires after 10 minutes.

The callback is public because the provider redirects a browser to it, but it
does not trust browser-supplied workspace/provider identifiers. Those are
recovered from the encrypted state generated by an authenticated workspace
request.

Return paths must be relative same-origin paths, preventing an OAuth callback
from becoming an open redirect.

## Confidential X web app

This adapter is designed for an X OAuth 2.0 confidential Web App / Automated
App. Token exchange and refresh use HTTP Basic authentication with:

```text
X_CLIENT_ID
X_CLIENT_SECRET
```

Configure the exact callback URL in the X developer application:

```text
OAUTH_CALLBACK_URL=https://api.example.com/v1/channels/oauth/callback
```

The same callback can be registered with LinkedIn.

## Account reconnect

Connecting an account that already exists for:

```text
workspace + provider + provider account id
```

updates its encrypted credentials instead of inserting a duplicate social
account.

This enables Reconnect after:
- permission changes
- token expiry
- newly requested analytics scope

## UI

The Channels page now exposes real connect/reconnect actions for:

- LinkedIn
- X

The browser asks the Next.js BFF to start OAuth. The BFF authenticates the
workspace request to the API and returns only the provider authorization URL.
Provider credentials never pass through client JavaScript.

After provider authorization, the API callback redirects to the workspace
Channels page with a success/error result.

## Environment

```text
WEB_APP_URL=http://localhost:3000
OAUTH_CALLBACK_URL=http://localhost:4000/v1/channels/oauth/callback
OAUTH_STATE_SECRET=<32+ random bytes>

X_CLIENT_ID=
X_CLIENT_SECRET=
X_SCOPES=tweet.read tweet.write users.read offline.access
```

Production must use the exact callback URL registered with each provider.

## Tenant-safe response caching

During the provider OAuth review, Stage 7 also removes the global Nest
`CacheInterceptor`.

SoStats workspace authorization is header/user-context based. A global GET cache
whose key is not explicitly workspace-aware can cache authenticated resource
responses under a shared URL. OAuth callbacks are also stateful GET requests and
must never be served from a response cache.

Caching can be reintroduced later for specific read models with explicit keys
that include workspace and relevant query dimensions.

## Capability scope

Stage 7 deliberately starts X with text publishing plus post analytics.

The X API also supports media upload, but SoStats should add provider media
attachment support as a separate slice that connects the Stage 6 Media Library
to provider-native media upload APIs without mixing that complexity into the
provider-neutral text path.
